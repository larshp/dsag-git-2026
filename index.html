What is abapGit?

An open-source Git client for ABAP development. It turns SAP development objects into files you can branch, review, share, and automate.</> For developers, in the development system.↻ A developer can update it at any time.

Git and the agents

Where this comes from

Two groups have looked at what actually makes AI pay off on a codebase. Neither of them is talking about ABAP — and both land on the repository.

DORA

dora.dev/ai

Google’s research programme on software delivery. The 2025 report on AI-assisted development, and the capability guides behind it — including the one on version control.

Factory

factory.com/agent-readiness

An evaluation framework that scores a repository on how ready it is for autonomous agents — documentation, tests, CI, modularity — and publishes the results for open-source projects.

Git and the agents · 01

Agents need files

A coding agent reads, diffs and patches files. ABAP objects live in the database, where it can do none of that.

SAPObjects in the database
abapGit
GitFiles in a repository
Nothing new to build

The serialisation that makes ABAP reviewable by a person is the same one that makes it readable by a machine.

Git and the agents · 02

The safety net

Generated code is only safe to try when it is trivial to inspect and to undo.

Strong version control practices are the essential safety net that allows teams to experiment with AI-generated code confidently.DORA · Version control
Revert

A bad suggestion is one command away from gone.

Audit

The history says what changed, when, and on whose account.

Review

A pull request puts a person in front of the change before it lands.

dora.dev/ai

Git and the agents · 03

Something has to check

An agent writes code far faster than a person can read it. Continuous integration is what keeps up.

It builds

Syntax and activation checked on every push — abaplint does it without an SAP system.

It is tested

ABAP Unit says whether the behaviour still holds, not just whether it compiles.

You hear back

The verdict lands on the pull request in minutes, before anyone reads a line.

More change needs more checking

DORA is blunt about it: without automated testing, mature version control and fast feedback, more change just means more instability.

dora.dev/ai

Git and the agents · 04

Iterate off stack

An agent’s first ten attempts should not land anywhere near a real system.

No system in the loop

abaplint parses and checks a plain checkout — no SAP instance, no logon.

Code that runs

open-abap executes ABAP and its unit tests on Node, so an agent can try what it just wrote.

Nothing to damage

Seconds per attempt, against a checkout rather than your development system.

Cheap attempts, safe attempts

The loop an agent needs — write, run, read the error, try again — is one you would never want it running inside a live stack.

Git and the agents · 05

The repository is the context

An agent is only as good as what it can see. In a repository everything it needs sits in one place.

The code

Source, and the tests that say what it is supposed to do.

The docs

Written beside the code instead of in a separate system.

The instructions

Prompts and agent configuration, versioned like everything else.

Better codebases, better outcomes

Factory scores repositories on documentation, tests, CI and modularity — the same things that already made a codebase good for people.

factory.com/agent-readiness

Git and the agents · 06

A person still decides

Everything so far makes a change cheap to produce and cheap to check. None of it makes the call.

A proposal, not a fact

The change arrives as a pull request and sits there until someone acts on it.

A diff you already read

Reviewers see exactly what moved, in the form they look at every day.

An explicit merge

Nothing reaches the system because a model was confident about it.

The agent proposes

Git already had the gate. Agents change how fast the queue fills up, not who is accountable for what goes through it.
